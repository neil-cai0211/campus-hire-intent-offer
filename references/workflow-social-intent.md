> **不走审批、不批量、不进 people.js**， Neil 逐项口述 ⇒ AI 生成 PDF + 图片。

| 信号 | 走哪条链路 |

## 标准流程

```
1. **连着不间断地「选项式」提问**（Neil 2026-11-13 明确偏好，别再改回去）：
   - 一次用 `AskUserQuestion` 给 **3–4 题**，每题都是可点选的选项（带「推荐」+ 自定义输入）；
   - 一批答完**立刻接下一批**，中间不插系统探查、不插长篇说明、不等待；
   - 11 项拆两批：`①汇报职级 ②汇报对象 ③职级 ④转正薪酬` → `⑤拆分比例 ⑥试用期比例 ⑦月数+入职日 ⑧有效期`。
   - 🚫 **不要**「一次性把 11 项列成文字清单让 Neil 自己打字填」——Neil 明确说「不喜欢全部写进去」；
   - 🚫 **也不要**一题一答中间夹大段组织架构探查（会被嫌慢）。系统侧核对放在开问**之前**或全部答完**之后**。
   - ⚠ 第 ⑥ 项「试用期收入比例」必须**单独一题**、不可与拆分比例合并：2026-11-13 薪酬口径事故就出在套了通用 85%。
2. 收到全部项 → 组装 JSON 配置
3. 跑 gen-intent.js 生成 PDF
4. 跑 make-insert-png.js 生成图片
5. **看图核验**（不能只看脚本日志）→ 有错就改配置重跑
6. present_files 交付图片 + PDF
```

### ⚠ 第 5 步不能省

脚本「成功」≠ 内容正确。2026-11-12 那次脚本报 `WORD_OK`，但图上：

- 称呼印的是**模板示例人名「林清云」**（模板改版了，硬编码没命中）
- 有效期印的是「**年NaN月NaN日**」（配置字段没写进去）
- 固定部分比例文字是「80%/5%/15%」，而金额是 75/5/20 的数（自相矛盾）

这三处**都没报错**。⇒ **必须裁图看**，至少看抬头、日期/试用期、薪酬、有效期四段。

## 固定部分比例（⚠ 硬约束）

比例**由序列决定**，不是由岗位性质决定：

| 序列 | 比例 | 备注 |
|---|---|---|
| 专业/技术序列（80/5/15） | 基本 80% / 保密 5% / 绩效 15% | tech 模板默认 |
| **管理序列（75/5/20）** | 基本 75% / 保密 5% / 绩效 20% | ⚠ 模板正文写死 80/5/15，**必须替换** |
| 销售线（95/5） | 基本 95% / 保密 5% / 无绩效 | sales 模板 |

### ⚠⚠ 比例文字是模板正文里的普通字，不是下划线槽位

R13 三列的「占目标税前收入满额的**80%**，」是**正文文字**，
字符级替换（下划线槽位）**改不到它**。

⇒ 金额填对了但比例文字没改 ⇒ 意向书上「75% 的钱」配「80% 的字」，
**自相矛盾，且不报错**。

⇒ 必须用 Find/Replace 单独替换（`config.js` 的 `templates.tech.texts`）：

```js
{ cell: '13,2', from: '占目标税前收入满额的80%，', field: 'basicPctText' },
{ cell: '13,3', from: '占目标税前收入满额的5%，',  field: 'secretPctText' },
{ cell: '13,4', from: '占目标税前收入满额的15%，', field: 'perfPctText' },
```

## 配置 JSON

```json
{
  "no": 100,
  "name": "<候选人姓名>",
  "job": "主管",
  "location": "福建福州及您参与的项目或工作任务所涉及的区域",
  "dept": "后端组",
  "boss": "VP",
  "probMonths": 6,
  "probRatio": "100",
  "fullInc": "28000",
  "basic": "21000",
  "secret": "1400",
  "perf": "5600",
  "basicPct": "75",
  "secretPct": "5",
  "perfPct": "20",
  "blankDates": true,
  "endYears": "3",
  "outName": "<姓名>-社招-<职位>",
  "validYear": "2026",
  "validMonth": "11",
  "validDay": "14"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `probRatio` | ✅ | 试用期比例（**85** / **100** / 其他），不带 % |
| `basicPct` `secretPct` `perfPct` | ✅ | 三项比例，不带 % |
| `blankDates` | 否 | `true` = 入职日期与合同终止日留空 |
| `validYear/Month/Day` | ✅ | 告知有效期，**算出来填进去**，别手写 |

### ⚠ 比例与金额必须自洽（脚本会校验）

`basic + secret + perf` 必须等于 `fullInc`；
`basic/fullInc` 四舍五入后必须等于 `basicPct`（其余两项同理）。

不符 ⇒ 脚本 `exit 3` 中止，不产出文件。

### ⚠ 告知有效期要算，不要手写

`valid-date.js` 的 `computeValidDate(baseDate)`：

```js
const { computeValidDate } = require('./valid-date');
const v = computeValidDate('2026-11-12');   // → { year:'2026', month:'11', day:'14', ... }
```

规则：**N 天 = 从发送当天起算、含当天**。3 天 ⇒ 11-12 / 11-13 / 11-14。

⚠ **意向书先生成、offer 后发**。跨天发送时用 `OFFER_BASE_DATE` 指定实际发送日重跑，
否则有效期对不上（offer 表单里的「offer有效期」和意向书必须一致）。

## 「留空」模式（blankDates）

**入职日期待定**时，不要把模板的示例值（如「2026年11月2日」）印在发给候选人的文件上。

`blankDates: true` ⇒ 把那几格填成**等长空格**（下划线格式完整继承）：

- R5C2 年/月/日 → `    年  月 日`（`□___年__月__日`）
- R6C2 终止月/日 → `    月    日`

⚠ 空格数量 = 原槽位长度 ⇒ 下划线视觉完整，**看不出是占位**。
⚠ `blankDates: true` 时**不校验** year/month/day/endMonth/endDay 是否存在；
`false`（默认）时缺这些字段 ⇒ `exit 3`。

## 脚本

`$HIRE_SKILL_DIR/scripts/gen-intent.js`

```bash
node scripts/gen-intent.js '<配置JSON>'
```

- 模板路径从 `config.js` 的 `templates.tech` 取（**不写死本机路径**）
- `HIRE_WORK_DIR` 中间目录（ps1 + json）**必须纯 ASCII**
  （ps1 源文件被 PowerShell 5.1 按 GBK 读，中文路径会破坏解析）
- `HIRE_OUT_DIR` PDF 输出目录，默认 `$HIRE_WORKSPACE/out`

### 脚本内置的三道保险（2026-11-12 加）

| # | 保险 | 挡什么 |
|---|---|---|
| 1 | **必填字段校验** | 缺字段 ⇒ `exit 3`。挡「有效期印成 NaN」 |
| 2 | **金额/比例自洽校验** | 合计≠满额、或比例对不上 ⇒ `exit 3` |
| 3 | **称呼自动探测** | 模板示例人名改版 ⇒ 自动找「X：您好」取名；找不到 ⇒ 中止 |

⚠ 第 3 条的实现：正则 `^([\u4e00-\u9fa5]{2,4})\uff1a\u60a8\u597d`
**通过 JSON 传给 PS**（ps1 源文件必须是纯 ASCII，中文字面量会破坏解析）。

### 为什么称呼要自动探测

模板的示例人名**每次改版都可能变**：

| 模板版本 | 示例人名 |
|---|---|
| 2025 版 | 赖沄葱 |
| **2026-11-04 版** | **林清云** |

硬编码 `paraReplaces: [{from:'赖沄葱'}]` 在新版上**替换不命中且不报错** ⇒
意向书上印的是模板示例人名。⇒ 改成运行时探测。
