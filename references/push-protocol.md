# 交付前确认与推送规范

> 适用范围：任何需要 Neil 确认、或需要推送到 GitHub 的任务。
> 核心：**先说清「要你确认什么 / 要你定什么」，再讲技术细节。**

## 一、输出顺序（硬规则）

每次回复 Neil，按这个顺序：

| 顺序 | 内容 | 说明 |
|---|---|---|
| **1** | **待确认 / 待办事项** | 放在最前面。编号列出，每条一句话说清「问的是什么、为什么需要你定」 |
| 2 | 已完成的事 | 一句话结论 + 关键数字 |
| 3 | 技术细节 / 踩坑 | 只写非显然的、影响后续复用的 |
| 4 | 交付物 | 文件路径 / 链接 |

**禁止**：把「需要你确认」的内容埋在长段落中间，或放在最后当补充说明。
Neil 的原话诉求是「放到需要我确认或者代办的前面」。

## 二、待确认事项的写法

每条包含四要素，缺一不可：

```
1. <问题一句话>
   我的建议：<具体选项>
   依据：<为什么这么建议；已实测的标「已实测」>
```

- **要具体**，不要「入职日期请确认」这种空话，要写「意向书的入职日期是否用审批里的 2026/11/06」
- **带建议和依据**，Neil 可以只回「同意」或改一个数字
- **区分已确认 / 待确认 / 必问**：

| 标记 | 含义 | 处理 |
|---|---|---|
| 🟢 已确认 | Neil 明确说过或已跑通核对过 | 直接执行 |
| 🟡 待确认 | 有推断但需拍板 | 列入待确认清单 |
| 🔴 必问 | 遇到未见过的岗位 / 情况 | **先问再填**，不自行推断 |

## 三、推送到 GitHub 前的自检清单

推送前必须自查，**并在回复里说明检查结果**：

| # | 检查项 | 判据 |
|---|---|---|
| 1 | 敏感信息脱敏 | 无真实姓名、手机号、邮箱、token、内部标识、本机绝对路径（用户名） |
| 2 | 凭证扫描 | `ghp_` `appSecret` `robotCode` `corpId` 私钥 等零命中 |
| 3 | 本地私密文件被排除 | `.gitignore` 覆盖 `config.local.*`、运行产物、日志 |
| 4 | 功能仍可用 | 脱敏后重新 require / 跑一遍校验脚本，确认没把功能改坏 |
| 5 | commit message 完整 | 有正文说明「做了什么 + 为什么」，不是只一句标题 |
| 6 | 远端可见性正确 | 涉及公司内部信息的仓库 → **私有** |
| 7 | 推送后验证 | 远端文件清单与本地一致，commit 已上 |

### 脱敏处理原则

| 类型 | 处理方式 |
|---|---|
| 真实姓名 | 移到 `config.local.js`（gitignore），仓库内用占位符 `<负责人>` |
| 手机号 / 邮箱 | 同上；或用 `<HR手机号>` 占位 |
| 本机用户名路径 | 参数化为 `$HOME` / `$TEMP` / 环境变量 |
| **工作区路径**（`D:\AI-Workspace\...`） | **保留** —— 不含个人身份信息，且是运行必需；用环境变量覆盖 |
| 公司模板路径 | **保留** —— 模板零副本原则要求引用原件；仓库本身设为私有 |

## 四、commit message 写法

```
<type>: <一句话标题（≤50字）>

<正文：做了什么 + 为什么这么改 + 影响什么>

<可选：关键坑位提醒>
```

- type：`feat` / `fix` / `docs` / `chore` / `refactor`
- 身份：公开仓库用 `neil-cai0211@users.noreply.github.com`（不写企业邮箱进 commit 元数据）
- **正文要能独立看懂** —— 半年后回看 commit 不依赖上下文

## 五、给 Neil 的推送汇报模板

```
## 已推送

仓库：<名称>（<公开/私有>）
commit：<短 hash> — <标题>
文件：<N 个文件，+X 行>

改动要点：
- <要点1>
- <要点2>

自检：
- 脱敏 <通过/发现N处已处理>
- 凭证扫描 零命中
- 本地私密文件已排除
- 功能验证 <通过>

待你确认：
1. <问题> — 我的建议：<选项>
```

## 六、什么时候要先问再推

| 情况 | 处理 |
|---|---|
| 只是常规同步（文档、脚本、修复） | 推完汇报即可，不必事前问 |
| 涉及**发布 / 部署 / 对外可见性变更** | 先问 |
| 涉及**删除既有文件或改写历史** | 先问 |
| 涉及**未确认的业务口径** | 先问，别把待确认的口径写进 commit |
| 仓库要从私有转公开 | 先问（必须重跑一轮更彻底脱敏） |
