# 链路一B · 社招录用审批（无需用人部门筛选）

与校招链路一（`workflow-approval.md`）**是两条不同的流程**，字段与口径都不同。

**入口差异**：社招流程条 = `简历初筛 人才推荐 | 面试 | 录用审批 | offer | 背调 | 待入职 | 入职`
（校招多出「考试 / 测评 / 用人部门筛选」）。社招候选人**必须面试通过 + 面试评价全部结束后**才出现「录用审批」按钮。

## 卡片匹配

同名多卡是常态（例：候选人A 与一位姓名近似的候选人）。按**应聘职位关键字**筛，并优先选**带「录用审批」按钮**的那条。

## ⚠ 填写顺序（硬约束，顺序错了跑不出完整表单）

**表单字段之间有依赖，不能随意换序。** 顺序错了会出现「薪酬只有 3 个框」
「入职部门被清空」「提交时字段是空的」这类问题，而且**不报错**。

### 唯一正确的顺序

| 步 | 动作 | 为什么必须在这个位置 |
|---|---|---|
| **1** | **试用期**（选具体月数，如 3个月） | 🔴 **最关键**。选完立刻把薪酬区从 3 个框展开成 6 个（试用期/转正后各 3 项）+ 2 个合计。**不先选这个，后面找不到 6 个槽位** |
| **2** | **职级**（点进「XX序列-S」再选级） | ⚠ **必须先于岗位**（2026-11-03 实测）。**先选岗位再选职级会失败** —— 岗位树的弹层还挂在 DOM 里，职级下拉点不开（树里只有 8 个分类节点、没有序列节点） |
| 3 | 入职岗位（树选：分类 → 岗位） | 触发岗位联动。⚠ 「技术支持专员」这类岗位在**营销**分类下，不在技术分类下 |
| 4 | 入职日期 / 转正日期 | 转正日期 = 入职 + 试用期月数 |
| 5 | 合同主体 | 选完自动带出入职联系人与电话（**不要手填**） |
| 6 | 录用类型 / 报到地址 | 普通枚举 |
| 7 | 汇报对象（搜 Leader 姓名，**有随机性必须重试**） | 联想列表不稳定 |
| 8 | 工作城市（省 → 市两级） | 用 `.select-world-city` 选择器 |
| 9 | **薪酬 6 项**（JS 赋值，见下） | 依赖第 1 步展开的两套槽位 |
| 10 | **入职部门**（组织架构树选） | ⚠ **必须最后填**。填完后若再触发其它联动，可能被系统重算覆盖（实测选中岗位后清空过一次） |
| 11 | blur（点 HRBP 再按 Tab） | el-select 类字段必须 blur 才写进 Vue model |
| 12 | 校验 → 点页脚「确定」→ 弹窗内「确定」 | 提交 |

### 三条不能违反的规则

1. **试用期必须第一个填**，否则薪酬区不展开 → 只能填到单套 3 个框，转正后金额无处可填。
2. **入职部门必须最后填**，否则会被联动重算清空。
3. **填表与提交必须一站式**（同一个页面会话内完成，中间不 `goto` / `reload`），
   因为**草稿不保存**，刷新后已填字段全丢。

### 第四条（2026-11-03 新增）

4. **职级必须先于岗位**。反了职级永远选不中，且不报错。

### 标准执行形态

```
填表 → 校验（关键字段 + 两个「工资合计」）→ 页脚「确定」→ 弹窗「提交审批」→ 弹窗内「确定」
```
校验不通过就**中止提交**，不要带着残缺数据点确定。

## 薪酬：转正前 / 转正后两套字段

⚠ **表单里有 6 个薪资输入框**（试用期/转正后 各 3 项）+ 2 个合计。

**两个必须知道的机制**（2026-10-30 实测）：

**① 薪酬区的「两套」由「试用期」下拉触发** —— 初始状态只有 3 个框（基本/保密/绩效），
选了具体的试用期月数（如 3个月）后，**立刻展开成试用期/转正后两套 6 项 + 两个合计**。
选岗位、选职级、选合同主体都**不会**触发 —— 只有「试用期」会。
⇒ **试用期必须第一个填**（见上文「填写顺序」第 1 步），否则后面找不到 6 个槽位。

**② 薪资输入框不能用键盘输入** —— `page.keyboard.type()` 填进去值会被组件重置回空。
必须用 JS 赋值 + 派发事件：

```js
const setter = Object.getOwnPropertyDescriptor(window.HTMLInputElement.prototype, 'value').set;
setter.call(inp, val);
inp.dispatchEvent(new Event('input',  { bubbles: true }));
inp.dispatchEvent(new Event('change', { bubbles: true }));
inp.dispatchEvent(new Event('blur',   { bubbles: true }));
```

填完「工资合计」会自动算出，可用来验证比例是否对。

**定位方式**：薪资区在 `.el-form-item` 里，但**它们的 label 是空的**，
要靠父级 `innerText` 推断字段名（`试用期基本工资` / `转正后保密津贴`…），
不能靠 label 元素，也不能靠 placeholder 顺序（会串位）。

**通用口径（技术/职能/品牌营销线以外）**：
- **转正后**：基本工资 80% + 保密津贴 5% + 绩效工资 15% = 100%
- **转正前（试用期）**：基本工资 80% + 保密津贴 5% + **无绩效** = 85%

例（候选人A，转正满额 4500）：

| 字段 | 值 | 比例 |
|---|---|---|
| 转正后基本工资 | 3600 | 80% |
| 转正后保密津贴 | 225 | 5% |
| 转正后绩效工资 | 675 | 15% |
| 转正后工资合计 | 4500 | 100% |
| 试用期基本工资 | 3600 | 80% |
| 试用期保密津贴 | 225 | 5% |
| 试用期绩效工资 | 0 | — |
| 试用期工资合计 | 3825 | 85% |

**销售线 / 品牌营销线（平面设计师除外）**：95% 基本工资 + 5% 保密津贴（无绩效），试用期同比例取 85%。

**表单会实时自动算「工资合计」**，填完核对合计数即可验证比例是否对。

## 提交：两段式

1. 填完点**表单页脚**的「确定」（在 `取消 / 保存草稿 / 确定` 三个里）→ 弹出「提交审批」对话框
   - 对话框内容：审批通过后需手动发送offer + 审批人链（见 config.local.js 的 approvalChain）
2. 再点**对话框内**的「确定」→ 提交完成

⚠ **对话框的按钮不是 `<button>` 元素**，要用 Playwright locator 在 `.el-dialog:visible` 范围内按文本「确定」定位；用坐标点会落到对话框后面的页面上（实测把页面导航到了组织架构）。

**完成判据**：卡片按钮变为 `撤销审批 / 催办 / 发送Offer`，状态标签显示「录用审批 | 审批中 | <当前审批人>」。

## 本链路的坑

1. **联想列表有随机性**：汇报对象、工作城市的联想可能不出现 → **必须重试**（汇报对象最多 5 次，工作城市 4 次）。
2. **表单字段不按直觉分组**：薪资在「其他信息」区、在 `.el-form-item` 之外；入职部门是自由文本框。
3. **入职部门要最后填**：填完后若再触发其它联动，可能被系统重算覆盖（实测选中岗位后清空过一次）。
4. **联系人别手填**：草稿可能残留上次的值，用 JS 直接赋系统自动带出的值最稳。
5. **同名卡片**：按应聘职位 + 按钮双重匹配。
6. **页面会保存草稿**：填错可以直接刷新页面重填，不用从头再来（但刷新会丢失联想组件的交互态）。

## ⚠ 八个必须知道的系统行为（都实测过）

### 0. ⚠⚠ 提交「确定」时，**弹窗里的「确定」点不中** → 审批实际没提交

2026-11-03 实测：填完表单 → 点页脚「确定」→ 弹出「提交审批」对话框 →
**弹窗出现但提交没生效**（重新进审批页，落库值全空，页面仍是可编辑表单）。

原因：对话框的「确定」按钮**不是 `<button>` 元素**，是 `span`/`div`；
用 Playwright locator 在 `.el-dialog:visible` 里按文本「确定」定位会失败
（`:visible` 在这个对话框上匹配不到），坐标点又可能落到对话框后面的页面上。

✅ **可靠做法**：遍历 `.el-dialog / .el-message-box / [role="dialog"]`，
在**可见**（width>100 && height>60）的对话框里找 innerText 恰为「确定」的元素，
取其 `getBoundingClientRect()` 中心坐标 → `p.mouse.click(x, y)`。

**提交成功的判据**（别只看脚本日志）：
- 重新进 `approval-detail` 读落库值 —— 字段有值、页面**不再可编辑**（按钮变成「撤销审批」等）
- 卡片状态标签显示「录用审批 | 审批中 | <当前审批人>」

### 1. 入职部门必须从组织架构的树里「选」，不能打字

`入职部门` 看起来是普通输入框（`placeholder="请在“组织架构”处设置部门"`），但它其实是
`qj-dropdown-menu qj-popper dept-dropdown` + `el-tree department-tree` 组件。

**正确路径**：点开下拉 → 点 `CS Dpt.(客户成功线)` 的**展开图标**（不是文字）→ 出现子部门
（Deployment 发货部署部 / OnSite Support 现场支持部 / **Implementation 远程实施部** /
Merchant Services 商户服务部 / Help Desk 技术支持部 / Business Management 业务管理部）
→ 点 `Implementation(远程实施部)` 的展开图标 → 出现 **远程实施组** / 服务小组
→ **点「远程实施组」的文字**（不是展开图标，它是叶子节点）。

⚠ 用 `.el-popper:visible` 选浮层**匹配不到**这个下拉（class 是 `qj-popper`），
必须用 `.dept-dropdown`。
⚠ **必须先选岗位再选部门**，否则树不加载（草稿态下岗位已选时，输入框可能不可见）。

⚠⚠ **叶子节点必须用 JS dispatch click，坐标点击不落位**（2026-11-03 实测）：
点 `.tree-item-content` 的坐标后，input.value 和 innerText **都还是空**，
但用 `dispatchEvent(new MouseEvent('click', {bubbles:true}))` 打在同一元素上**立刻落位**。

```js
await p.evaluate((leaf) => {
  for (const e of document.querySelectorAll('.tree-item-content')) {
    if ((e.innerText || '').trim() !== leaf) continue;
    e.dispatchEvent(new MouseEvent('click', { bubbles: true, cancelable: true, view: window }));
  }
}, leaf);
```

⚠⚠ **组织架构树的标签不在 `.custom-tree-node` 里**（那个是空的），
要用 `.el-tree-node__content` 的 `innerText` 或 `title` 属性
—— 与**岗位树相反**（岗位树的标签才在 `.custom-tree-node`）。

⚠⚠ **树的节点不在 `.single-select-dept-wrapper` 里**，它在 `.dept-dropdown` 里，
两者是**兄弟节点**。查找节点要**全局查** `.el-tree-node__content` 再按可见性过滤，
不要限定在某个 wrapper 内。

**「技术支持组」的真实路径**（2026-11-03 定位）：
`CS Dpt.(客户成功线)` → `Help Desk(技术支持部)` → **`技术支持组`**
（编制 **160/148**，预增 **11/0**，缺编 **12** —— 有预增，所以**不触发超编弹窗**）。

**选中成功的判据**：输入框有值，且下方出现该部门的编制信息
（如 `编制/占编 160/147 | 预增/预减 12/2 | 缺编 13`）。**只显示文字、没有编制信息 = 没选中。**

### 2. el-select 类字段必须触发 blur 才会写进 model

选完部门/城市这类 `el-select` 组件后，**必须让焦点离开该字段**（点另一个输入框后按 Tab），
否则值只停留在 DOM 上、不会写回 Vue model → 刷新后丢失、提交时不带上。

```js
// 选完部门后
await p.mouse.click(otherInput.x, otherInput.y);
await p.keyboard.press('Tab');
await p.waitForTimeout(1200);
```

### 3. 「保存草稿」按钮会清空表单 —— ⚠ 但只对普通字段成立，**JS 赋值的薪资是例外**

实测：点「保存草稿」后刷新，**普通输入框字段会变成空**；而不点它直接刷新，草稿是保留的。
系统的自动保存（失焦即存）已经生效，**「保存草稿」反而会重置普通字段**。

⚠ **但 JS 赋值的薪资字段是例外**（2026-11-03 实测）：填完薪资 → 点「保存草稿」→
**重新加载页面，薪资仍留存**（4800/4800/300/300/0/900，合计 5100/6000 都在）。

⇒ **「保存草稿」可以用来持久化薪资**，用来让审批留值与 offer 表单对齐
（见 `workflow-social-offer-onespass.md` 的「必审字段被修改」一节）。
但普通字段可能被清空，所以**保存后必须重新加载验证**，不要假定全保住。

**验证持久化的正确方式**：填完 → 保存草稿 → 刷新 → 重新读值。

### 4. 草稿不保存：填表与提交必须在同一个页面会话内

刷新页面后，**已填的字段全部丢失**（实测：填完 15 个字段，读回全空）。
自动保存（失焦即存）对普通输入框有效，但 **JS 赋值的薪资字段不触发**，
且整体草稿在刷新后不恢复。

⇒ **填表与提交必须写成「一站式」脚本**：填 → 校验 → 点确定 → 弹窗确定，
中间**任何时候都不要 goto / reload**。分两次脚本跑（先填、另一次提交）必然失败。

### 5. 工作城市是 `select-world-city`，不是标准 cascader

浮层结构：`el-popover el-popper select-world-city` + `cascader city-list-content`。
用 `.el-cascader__dropdown:visible` **匹配不到**，要用：

```js
const prov = p.locator('.select-world-city:visible').getByText('福建省', { exact: true }).first();
const city = p.locator('.city-list-content:visible, .select-world-city:visible').getByText('福州市', { exact: true }).first();
```

两级都要点（先省后市），点完读回确认是 `福建省/福州市`。

### 6. 下拉选项有两个坑：`:visible` 匹配不到 + 动画期 height = 0

Element UI 的 `el-select-dropdown__item`：
- 用 `p.locator('.el-select-dropdown:visible .el-select-dropdown__item')` **经常匹配不到**（浮层已渲染，但样式判定为不可见）
- 动画中间态下 `getBoundingClientRect().height === 0` ⇒ 用 `h > 8` 过滤会把选项全部排除

⇒ **优先用 `p.locator('.el-select-dropdown__item').filter({hasText: text}).first().click()`**
（Playwright 内部处理动画与可见性），失败再用底层坐标兜底（兜底时**只按 width 过滤，不能按 height**）。

同理，卡片上的「录用审批」按钮 **hover 才显示**，不 hover 时 `getBoundingClientRect` 全为 0 → 取不到坐标。
必须先 `cardLoc.hover()` 再取坐标。

### 7. 部门树的节点文字可能与 fullPath 段不完全一致

按 `fullPath` 逐级展开时，用**括号前的英文名做宽松匹配**（取文本最短的候选），
不要用全段精确匹配 —— 实测 `Implementation(远程实施部)` 这种带括号的段会匹配失败。
