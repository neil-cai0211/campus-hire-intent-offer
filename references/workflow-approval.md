# 链路一 · 录用审批

**目的**：把候选人从「简历初筛」推进到「审批中」，解锁 offer 环节。
**产出判据**：卡片状态标签变为「**审批中**」，按钮变成「撤销审批 / 催办 / 发送Offer」。

## 步骤

| # | 操作 | 关键点 |
|---|---|---|
| 1 | 列表页搜索姓名 | **同名多卡是常态**（每人常有多条记录，岗位不同）→ 按**应聘职位关键字**筛卡片，且优先选**带「录用审批」按钮**的那条 |
| 2 | 点卡片上的「录用审批」按钮 | ⚠ **不是**详情页右上角「进入 XX ▼」下拉——那是**改流程节点**的操作，会把候选人推到别的环节 |
| 3 | 已移库的人 | 卡片只有「移库 / 重新分配职位 / 恢复到流程」→ 先「恢复到流程」才能发起审批 |
| 4 | 填岗位 | `.multi-select-popover` + `.custom-tree-node` |
| 5 | 填职级 | `.xin-rank-select` + `.rank-select-tree` |
| 6 | 填汇报对象 | `.employees-department-box`，**需真实鼠标点击展开**（程序化点击不生效），搜名字后点 `.node-label` |
| 7 | 填部门 | `.qj-dropdown` + `.dept-dropdown`，**必须点 `.item-name`**，直接 fill 不绑定值 |
| 8 | 填工作城市 | el-cascader，点 `.cascader-menu__item-name` **两级**（省 → 市） |
| 9 | 填入职日期 | **2027/06/01**（录用审批口径，与offer页的07/01不同，见 templates.md） |
| 10 | 提交 | **连续两个弹窗**，见下 |
| 11 | **钉钉提醒当前审批人（Neil 本人身份，非机器人）** | 状态核验为「审批中」后执行，见 [钉钉审批提醒环节](dingtalk-approval-reminder.md)。先 `--dry-run` 预览 + Neil 确认，文案不带薪酬 |

## 提交的两个弹窗

**必须连点两次，漏一个就停在中间态**：

1. `.el-message-box` — 「已超出设定编制，不可继续操作，【XX部】的编制将超编1人（校验通过）」| 取消 · 确定
2. `.el-dialog` — 「提交审批 / 审批通过后需手动发送offer / 审批人」

**两个弹窗都必须用坐标点击**（`page.mouse.click` 取按钮中心），Playwright 的 locator 点击会失效。循环处理直到无弹窗。

## 坑

- **弹窗需坐标点击**：locator 点了会报 element is not visible 或静默失败。
- **完成判据是「审批中」**，不是「提交成功」提示。提交后卡片可能同时出现「发送Offer」按钮 → 说明已可进入链路三。
- **不要用详情页的流程下拉改节点**，会把候选人推错环节。
- 审批链路的表单字段（岗位/职级/部门/汇报对象）就是后续意向书与offer的口径来源，填错会一路传到候选人收到的邮件。
